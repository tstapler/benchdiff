## Concerns
- [ ] **C1. Wave W2 still has same-file and compile-order conflicts, contradicting "no two tasks in the same wave edit the same file".** 1.1.1a creates stubs `options.rs` and `svg/mod.rs` and the `pub mod` lines in `lib.rs`; in the same wave 1.2.1a fills `options.rs` (and needs `pub mod options` to compile) and 3.1.1a fills `svg/mod.rs`/`svg/writer.rs` (its Files list `svg/mod.rs`). Also missing from the ownership table: `svg/mod.rs` (touched by 1.1.1a W2, 3.1.1a W2, 3.2.4a W9, 3.3.2a W11), `test/images.test.js` (4.1.1a, 4.1.2a-c, 3.3.3a), `Cargo.toml`/`Cargo.lock`, `ci.yml`/`Makefile`. Story-level Files lists contradict the lib.rs freeze (1.1.2, 1.2.2 and 2.1.3 list `lib.rs`). Recommendation: make stub creation its own XS task in W1 (or move 1.2.1a and 3.1.1a to W3), add the missing files to the ownership table, and strip `lib.rs` from those story Files lists.
- [ ] **C2. Story 1.2.2 (W4) has ACs that need types from later waves.** The AC `charts: "bars"` -> "use none, delta, ranking, distribution" needs `ChartKind` (3.3.1a, W13); `chart-row` -> "did you mean chart-rows" needs the chart keys (added by 3.3.1a, W13); the valid-file AC needs `reference` (`Reference`/`VariantLabel`, W6-W7), `dimensions` (`Rule::parse`, 1.1.2b, same wave W4) and a matrix overlay type (`MatrixOptionsOverlay`, 2.2.2a, W12). The task cannot satisfy its own AC at its slot. Recommendation: either define the full key set and enums in `config.rs` at W4 with string-typed placeholders validated later, or move the unknown-key/enum ACs for chart/matrix keys to 2.2.2a and 3.3.1a and keep 1.2.2 to the keys that exist.
- [ ] **C3. `Comparison::Invalid` has no defined source for the matrix.** The kernel never returns `Invalid`: `compare()` emits it only for a base metric in `head.skipped` (compare.rs:185-194), and `Skipped` is an importer-side list of `(group,name,measure)` capped at `MAX_SKIPPED` (model.rs:104-136). Story 2.1.3's AC ("variant `merge` has a NaN sample for `Sort`") is also wrong against the importer: NaN lines are dropped and only an all-bad series is registered as skipped (`import/go.rs:77-78,124`). For labelled files the per-file `skipped` is usable; for axis splitting (`compare-by=impl`) skipped keys carry the raw name `Sort/impl=merge` and must go through dimension extraction to be attributed to a variant, which no task does. Recommendation: state that Invalid = "present in the reference set, absent from the variant but in that variant's skipped list (extracted like names)", say the cap-50 limit makes beyond-cap cases `Missing`, fix the AC to "all samples NaN", and add a task note to 2.1.2a/2.1.3a.
- [ ] **C4. Action `variants` integration gaps in `main()`/`buildArgs`.** (a) `main()` throws `no head files match` when `head` is empty (index.js, first lines of `main`); 4.2.3a only mentions `parseVariants`, `stage`, `buildArgs`, not relaxing this guard. (b) `buildArgs` always passes `--head-json /work/head.json` and the Action always exports `head-json-path`; what these mean for a matrix run (which variant?) is unspecified. (c) `expand()` splits on `[\n,]` (index.js:26), so `{a,b}` globs need a new single-pattern resolver, not `expand()`; the AC tests it but the task does not say a new helper is required. (d) `format`/`base-format` with variants (per-variant detection) is undefined. (e) the companion `counts` for matrix runs must include all keys `index.js` reads (`new`, `removed`, ...), and "sum of Compared verdicts and Invalid cells" leaves Missing cells uncounted; say so. Recommendation: add these to 4.2.3a/2.1.6a ACs.
- [ ] **C5. Task 0.2.1b is in no wave.** The wave table lists 49 of 50 tasks. 0.2.1b is the wall-clock human gate that 4.1.2a-c (W8-W10), 3.1.3a default theme (W4), 3.3.3a (W14) and 3.1.2a's width-table source depend on; the plan says "4.1.2a-c depend on the 0.2.1b outcome" yet schedules 4.1.2a at W8 with no gate. Recommendation: add an explicit gate row (after W1, before W8) and list which waves can proceed without it.
- [ ] **C6. ADR/plan cross-reference drift.** ADR-005 item 1 still says default reference follows "Action `head` input order", contradicting ADR-007 (`variants`, `head` untouched). ADR-004 item 6 says config `strict: true` while the plan (2.2.2, 4.2.1) and the README AC (5.1.1: identical kebab-case names across input/flag/key) use `dimensions-strict`. ADR-001's key list omits `thresholds`, `correction`, `reference`, `dimensions-strict`, `svg-embed`. Recommendation: fix those three sentences.
- [ ] **C7. No end-to-end test of the `config` input through the real wasm.** 1.2.4a validates argv and byte-copy of the staged config with the pre-existing committed wasm (which does not know `--config`); the first rebuilt wasm is W13 and 4.2.3b covers only `variants`. A bug in the `/work/config.json` path or in the binary's layering as seen through WASI (preopen only) would first surface in 5.1.3. Recommendation: add one Action-level case (config sets `threshold: 3`, input overrides to 7, expect effective 7 via `--print-config` or a report note) to 4.2.3b or 4.2.2a.
