# Pre-mortem: benchdiff-dimensions-svg
**Date**: 2026-10-31

Basis: `requirements.md` and `implementation/plan.md` (1,039 lines, read in full). Statements about GitHub behaviour are INFERRED unless the plan says a spike verified them; the plan itself lists none as verified (Unresolved Questions, first bullet).

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Hosted SVGs do not render inline for the repos that matter. The orphan-branch raw-URL mechanism (ADR-003) is unverified, needs `contents: write`, and by design falls back to text for private repos, fork PRs and GHES. Success metric 3 ("renders in comment, job summary, standalone") is met only for public same-repo PRs. The "fallback" is just the existing table, so for everyone else the SVG half of the feature delivers nothing. | Broken-image icons or a bare alt text in the first real PR comment (task 5.1.3a), or `charts could not be hosted: private` in every log line of the maintainer's own private repos. | (a) Widen the 0.2.1a spike matrix before G1 to include: Content-Type/`nosniff` of the raw URL through Camo, a private-repo run, a fork-PR run, a base64 `data:` URI variant in the step summary, and a repo-tracked path (`docs/` or release asset) variant. (b) Write the fallback ladder into ADR-003 now, with at least one rung that still shows the chart for private/fork runs (for example the SVG as a workflow artifact plus a collapsed `<details>` text rendering of the top rows), instead of deciding it after G1. (c) Re-state success metric 3 in plan.md as a per-repo-class support matrix (public same-repo / private / fork / GHES) with the expected output for each, and make 5.1.3a verify each row. (d) Make the fallback notice appear in the Markdown body, not only the log. (e) Give 4.1.2 a retention rule (see #5 note below) before any publish ships. | P1 |
| 2 | N-way report names a wrong or misleading winner and a flaky gate. The geomean is taken "over the intersection with the reference" per variant (task 2.1.5a), so a variant that skipped its slow benchmarks gets a better geomean than one that ran everything, and the headline still says "is fastest overall". The default reference is first-seen order, so the order of globs or files silently changes every delta. Holm (ADR-002) corrects only within a row across variants, not across hundreds of rows, so `fail-on-regression` on a 300-row matrix produces spurious Regressed cells. | A maintainer notices a variant is "fastest" while its column shows `-` in many rows; or `fail-on-regression` flips between reruns of identical code. | (a) Change 2.1.5a/2.2.1a: compute the headline geomean over the common row set (rows where every compared variant has a Present, non-Invalid cell) and print each variant's `n_used/n_total`; if the common set is under 3 rows or under half the rows, replace the "fastest overall" sentence with `not comparable: merge covers 9/15 benchmarks`. Add an AC for this with a fixture where one variant is missing its slowest rows. (b) State the reference choice in the headline (`reference: quick (first listed; set 'reference' to change)`) and add an AC that permuting input order with an explicit `reference` yields identical deltas. (c) Add to 2.1.4a an AC and README note that Holm is per-row only, plus a documented recommendation to pair N-way `fail-on-regression` with a threshold and `min-abs`, and add a seeded test: 300 rows of identical-distribution samples must not trip `matrix_failed` at the default threshold. | P1 |
| 3 | Data-driven problems are treated as config errors and fail the whole job. The failure policy says "config problems fail fast (exit 2)", but several of those errors depend on benchmark data that changes between runs: zero-match dimension rule, collision after residual extraction, `compare-by 'impl': no benchmark carries this dimension`, `reference` label absent, `label 'heap' matched 0 files` when a variant's benchmark job crashed. One renamed benchmark or one failed upstream job turns every PR red and produces no comment. | CI goes red on a PR that did not touch benchmarks; the sticky comment is missing and the log shows `matched 0 of 48 benchmark names`. | Split errors in plan.md's Risk Control into two classes. Static config errors (unknown key, bad enum, bad regex, bad label grammar) stay exit 2. Data-dependent errors (zero-match, collision, missing axis dim, missing variant file, absent reference) get a new `--on-data-error warn|fail` behaviour, default `warn` in the Action: render a visible notice comment ("dimension rule matched 0 of 48 names; showing two-way report") and fall back to the two-way or partial matrix; `dimensions-strict` is the opt-in to fail. Add ACs in 1.1.2c, 2.1.2 and 4.2.3 for each case, and a 4.2.3b e2e case where one variant file is empty and the comment is still posted. | P2 |
| 4 | Chart layout is wrong in real use even though every test passes. Text widths are estimated from a hand-copied AFM table, and snapshot tests (3.2.x, 4.2.2a) only lock bytes, so a clipped or overlapping layout becomes the committed golden. Long Go sub-benchmark names, CJK, 8 series x 30 rows and narrow mobile viewports are the likely failures; the only visual check is the owner's one-time look in 5.1.3a. | Labels run into bars or get cut at the card edge in the first release screenshot; mobile shows 760 px charts shrunk to unreadable text. | Add a verification step to 3.2.1a/3.2.2a/3.2.3a and 5.1.3a: render each golden SVG to PNG with a dev-only rasteriser (outside the wasm, for example `resvg` run from a script or CI job, not a crate dependency) and have a reviewer open the images for a fixed worst-case set (500-char name, CJK, RTL, 10 variants x 30 rows, 320 px-wide display). Add a geometric assertion in tests: for every `<text>` element, estimated width plus margin is inside its container, and no two label boxes overlap. Reject a golden update unless the PNGs are attached to the PR. | P2 |
| 5 | The default path or the shipped artifact drifts without anyone noticing. The byte-identity guard (0.1.1) is seven CLI cases built from one Go fixture plus native JSON, but the plan touches every importer (struct-literal fix in 1.1.1a), removes `action.yml` defaults (1.2.4a, so CLI defaults now silently supply threshold/min-abs/sort), and commits `dist/benchdiff.wasm` from three different integration tasks. Wasm reproducibility is left as a non-blocking open question, and tests in waves 14-16 run against a wasm built at wave 13. The Action runs the committed wasm, so a stale or non-matching binary ships old behaviour under the new tag. | `@v0` users see different threshold or sort behaviour with no input change; or the released wasm lacks `<picture>` output that the Rust source has; or the size gate fails at wave 13+ and forces a budget raise because headroom (480,000 vs a 450-480 KB projection) is thin. | (a) Extend 0.1.1a with one golden per importer format (Go, JMH, Criterion, Google Benchmark, native JSON, whichever exist) and one Action-level golden that runs `main()` through the real wasm with no tunable inputs and compares the full comment body and outputs. (b) In 1.2.4a add an AC that the binary's built-in defaults equal the old `action.yml` defaults (5, 0, delta, plus `format`, `title`, `tag`, `max-rows`) as an explicit test table. (c) Add a CI job that rebuilds the wasm from source and fails if it differs from `dist/benchdiff.wasm` (resolve the reproducibility question in W1 rather than deferring); make every integration task and 5.1.2a pass it. (d) Run 4.2.3b after the final rebuild or re-run it in W17. (e) Re-measure wasm size after 1.1.2b and again after 3.3.1a and fix the budget policy then, not at release. | P2 |

## Notes
- Retention (referenced in #1): the plan has no cleanup for `benchdiff-assets`. Every run adds commits and content-hashed files for every tag, and a default `git clone` fetches all branches, so repo size grows unbounded. Also, the Rollback instruction "delete branch `benchdiff-assets`" would break every image in historical PR comments. Treat as P2 if not folded into the #1 change.
- Considered and not ranked in the five: wasm size budget alone (folded into #5), `contents: write` acceptability (already an open question owned by Tyler), and execution overrun (the plan has a 25% checkpoint).
