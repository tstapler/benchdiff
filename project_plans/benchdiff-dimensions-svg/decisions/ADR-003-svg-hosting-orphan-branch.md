# ADR-003: SVG hosting via SHA-pinned raw URLs on an orphan branch, behind a swappable `publishImages()` seam

**Status**: Proposed. Becomes Final only when task 0.2.1 (real-PR rendering verification) passes. If it fails, execute the fallback ladder below and re-issue this ADR.
**Date**: 2026-10-31
**Project**: benchdiff-dimensions-svg

## Context
GitHub strips inline `<svg>`, `data:` URIs and (per the sanitizer allowlist) permits only http/https/relative `img src` plus `<picture>/<source srcset>`. Images are proxied through Camo, which fetches anonymously. Ranking from `research/pitfalls.md` section 1: orphan branch + `raw.githubusercontent.com/<o>/<r>/<sha>/<path>.svg` first (serves `image/svg+xml`, VERIFIED by curl), release assets last (REPORTED `application/octet-stream`), workflow artifacts need login so Camo cannot show them, `user-attachments` has no API, jsDelivr adds a third party. Whether Camo/raw render in a real comment AND a step summary, and how `prefers-color-scheme` behaves inside `<img>`, are UNVERIFIED.

## Decision
1. Delivery is **opt-in** (`charts` defaults to `none`). In the Action a non-empty `charts` implies embedding and hosting unless the user sets `svg-embed: false` (files only) or `publish-images: false` (text chart plus files); in the CLI embedding is off unless `--svg-embed` is given. `svg-embed` (`true|false|auto`) and `publish-images` (`true|false`) are flags, config keys and Action inputs with the same names (plan 3.3.1, 4.2.1). The publisher runs only when embedding is effective and `publish-images` is not false.
2. **Always** write `.svg` files to `svg-dir` and expose Action outputs `svg-dir` and `svg-paths`. Users who want a download link add `actions/upload-artifact` with `archive: false` themselves (the zero-dependency `index.js` cannot call the artifact service). Documented, with a README snippet.
3. **Hosted mechanism (v1)**: when the repo is public AND the token can write contents AND the event is not a fork PR (private/fork status read from the event payload at `GITHUB_EVENT_PATH`; non-PR events such as `push` or `workflow_dispatch` skip the fork check), commit the SVGs through the Git Data REST API (blob/tree/commit/ref via `fetch`, one commit per run, no extra dependency) to an orphan branch `benchdiff-assets` under a **content-hash path** `t-<12 hex of sha256(tag)>/<sha256-prefix>/<name>.svg` (the raw `tag` is never a path component: `validateTag` permits `.`, `..`, `:` and `/` because it only guards the HTML-comment marker), and embed `<rawBase>/<owner>/<repo>/<commit-sha>/<path>` with `rawBase` = `https://raw.githubusercontent.com` for github.com only (other `GITHUB_SERVER_URL` values, e.g. GHES, give `reason:'unsupported-host'`; API calls honour `GITHUB_API_URL`). URLs are immutable, which defeats raw and Camo caching. Concurrent runs retry on ref conflict (re-read, re-parent, exponential backoff with jitter, up to 5 attempts); a create-ref 422 "already exists" switches to the update path instead of failing.
4. **Otherwise** (private repo, fork PR, push failure, missing `contents: write`, GHES, unreadable event, `publish-images` false): follow the fallback ladder below, emit a `⚠️` line **in the Markdown body** (sticky comment and job summary, not only the log) naming the reason, the directory the SVGs are in (a path on the runner, never an artifact name, since `index.js` cannot upload artifacts) and an `actions/upload-artifact` hint for keeping them, and a `core.warning`-style log line. For `permission` the line also points to the README `permissions:` snippet, because a first run of `charts: delta` alone often meets a read-only default token (INFERRED: newer repositories and organizations default to read-only). Never fail the job.
5. **Seam**: `lib/images.js` exports `publishImages(files, ctx) -> Promise<{ urls: {[name]: string} } | { error: string, reason: 'private'|'fork'|'permission'|'push-failed'|'unsupported-host'|'no-event'|'disabled' }>`. `index.js` calls only this function. Core emits placeholder references `![alt](benchdiff-svg:NAME.svg)` and never knows URLs; `index.js` rewrites placeholders or strips them. Swapping the mechanism (jsDelivr base URL, gh-pages, a future first-party API) changes only `lib/images.js`.
6. **Dark mode**: default is ONE SVG with an opaque light card (readable on any page theme). `chart-theme: both` emits `-light`/`-dark` files and a `<picture>` element, expressed in core output as `<picture><source media="(prefers-color-scheme: dark)" srcset="benchdiff-svg:NAME-dark.svg"><img alt="ALT" src="benchdiff-svg:NAME-light.svg"></picture>`; `index.js` rewrites every `benchdiff-svg:` token and strips the whole block on fallback (plan task 3.3.3). Final default depends on task 0.2.1 findings.
7. Branch retention (revised in round 3; the earlier text said the branch may be deleted at any time, which breaks every image in historical comments): the publisher never deletes the branch, never force-pushes and never rewrites history, so commit-pinned URLs in old comments stay reachable (INFERRED: unreachable commits are eventually garbage-collected). A run whose content-hash paths already exist at the tip creates no commit. Growth is bounded by (runs x chart bytes, each SVG capped at 100 KB). A maintainer who squashes or deletes the branch to reclaim space breaks old images; rollback advice is to unset `charts`. Pruning by squash is out of scope for v1.
8. `pull_request_target`/`workflow_run` are explicitly not supported (untrusted benchmark names).

## Early gate (task 0.2.1)
Before building the publisher, publish a hand-written fixture SVG through a throwaway workflow and look at it in: (a) a PR sticky comment, (b) `$GITHUB_STEP_SUMMARY`; GitHub light and dark theme; OS light and dark; desktop and mobile; `<style>` with `prefers-color-scheme` honoured or not; `<picture>` honoured in both surfaces. Round-3 widening (pre-mortem failure 1): the `Content-Type` and `X-Content-Type-Options` of the Camo-proxied URL (taken from the rendered comment HTML), seven embed variants (plain raw URL, `<picture>`, `#gh-light-mode-only` fragments, artifact `archive:false` link, `github.com/.../raw/`, base64 `data:` URI, repo-tracked path), and three runs: public same-repo PR, private repo, fork PR. Record results in this ADR.

## Fallback ladder (decided now; the spike chooses which rungs are live per repo class)
Each rung is tried in order for a repo class; the text chart is the floor and always shows the chart's content, so no class loses the information.
1. **Hosted raw URL** on the orphan branch: public repo, same-repo PR or non-PR event, `contents: write`. Inline image in comment and summary.
2. **Alternative hosted base** through the same seam (jsDelivr for public repos; `github.com/<o>/<r>/raw/<sha>/...` for private repos if the spike shows it renders anonymously or with the viewer's session; a base64 `data:` URI in the **job summary only**, if the spike shows the summary keeps it): live only for the classes and surfaces where the spike observed it working. This is the rung that can still show an image for private or fork runs.
3. **Text chart (always available)**: the report carries the `Chart data (text)` block opened (`<details open>`) with the chart's exact rows plus the Unicode `▰` bars, the SVG files are written to `svg-dir` and listed in `svg-paths`, and users who want a download add `actions/upload-artifact` (`archive: false`; README snippet). This is what private, fork, GHES and permission-failure runs get at minimum, and it is what the standalone files serve for README and release notes.
4. In every case the `⚠️` reason line is in the Markdown body (item 4) so a reader of the comment or summary, not only of the log, knows why the image is absent and what fixes it.
Spike outcomes map onto the ladder: raw fails in the summary only -> rung 3 for the summary, rung 1 for the comment; raw fails everywhere -> try rung 2 (jsDelivr) then rung 3; nothing renders -> rung 3 only (charts stay useful as standalone files). The per-repo-class expected output is the support matrix in plan.md ("Success metric 3 as a support matrix"), verified in task 5.1.3a.

## Alternatives rejected
- Release asset (wrong MIME reported, needs a release), artifact URL (login), data URI / inline svg (stripped), `user-attachments` (no API), QuickChart-style renderers (data leaves runner), GitHub Pages (extra permission), `pull_request_target` (unsafe).

## Consequences
- Needs `contents: write` for the hosted path only; documented. Branch grows by one small commit per run.
- Side effects are disclosed to the user who opts in (triad review round 1): `action.yml` descriptions, a README section "Hosting images" and one step-log line state the permission, the `benchdiff-assets` branch and its per-run commit, retention (never pruned; deleting the branch breaks old images), that hosted images are readable by anyone with the URL (for a public repo, the audience of the comment), and that private repositories are never hosted and nothing is written there.
- Private repos get no inline images in v1 unless the spike shows a ladder rung 2 that works for them (known, documented); they get the open text chart and the files.
