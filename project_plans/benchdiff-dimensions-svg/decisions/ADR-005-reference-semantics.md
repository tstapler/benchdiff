# ADR-005: "Reference" is a fixed column (first input by default), best-per-row is only a ranking marker

**Status**: Accepted
**Date**: 2026-10-31
**Project**: benchdiff-dimensions-svg

## Context
Requirements say "default: first/fastest". "Fastest" differs per row, so a reference column cannot be "fastest"; changing it between runs also makes consecutive PR comments incomparable (`research/features.md` section 1 pattern 2; `research/ux.md` section 2).

## Decision
1. **Reference** = one column (variant label or axis value) shared by all rows. Default = the **first** variant in input order (CLI `--variant` order, Action `variants` input line order (ADR-007; `head` is untouched and never carries labels), or, when variants are split from benchmark names, the axis value first **encountered** walking `MetricSet.metrics`: files in the order given, glob matches sorted by path, metrics in file order). The order is a pure function of the input, so the same input always yields the same reference; a tie cannot occur within one pass and would break by label, byte-wise. When benchmark order is not under the user's control they should set `reference` (the README says so). Config/flag `reference` names a label explicitly; an unknown label is a config error listing the valid labels.
2. Every non-reference cell is `compare_pair(reference, cell)`; reference is the "base" side. The kernel is unchanged and orients by the HEAD-side metric's `better`, so the matrix compares `better` first: if a variant's `better` disagrees with the reference's, the cell is `Comparison::DirectionMismatch`, short-circuited before the kernel is reached, and excluded from verdict counting and geomean. When they agree the two values are equal, so the kernel runs on the unmodified variant metric (no clone or overwrite is needed). Ranking and geomean orientation likewise use the reference's `better`.
3. **Best per row** is a separate `ranking: Vec<usize>` plus a bold-the-best marker in the matrix and a rank number in charts. Bold, Rank and the headline's `has the best geomean` are **orderings, not tests**: only each variant against the reference is tested (item 2), so no report text claims a head-to-head win or loss between two non-reference variants ("fastest overall" and "loses in N rows" were dropped in triad round 2; the headline says `slower than reference in N of M rows`, counting the named variant's 🔴 cells, and the legend states that bold and Rank are untested orderings). It never changes deltas or sort by default (sort modes: `delta` (worst vs reference first), `name`, `input`, `rank`; `rank` exists only in the matrix's own `MatrixSort` enum and is an error on a two-way run).
4. If the reference is absent from a row: no deltas for that row, values shown, row listed in a warning line (first 10), and excluded from geomean. No automatic fallback to per-row best.
5. Geomean in two views (amended in round 3: a variant that skipped its slowest benchmarks must not win by omission). Per variant: over benchmarks present in both the reference and that variant, oriented by the reference's `better`, with zero/negative/non-finite excluded and counted; printed as `n=12/15`. Headline: over the **common row set** (rows where the reference and every compared variant are Present and not Invalid), with `common/total` printed; when the common set is under 3 rows or under half the rows the headline says `not comparable: <variant> covers 9/15 benchmarks` and names no winner. The headline also states the reference (`reference: quick (first listed; set 'reference' to change)`); with an explicit `reference`, permuting input order leaves every delta identical. Computed per `(measure, unit)` family and never mixed across families; the headline sentence uses the primary time-unit family only (else the largest), other families get their own table row.
6. Two-way base/head is not rerouted through this; it remains `compare()`. Conceptually N=2 with base as reference.
7. **What "regression" means in N-way (added after triad review round 1; the earlier text reused the word without defining it).** The reference is the baseline. A cell is `Regressed` when the pair kernel (threshold, `min-abs`, Mann-Whitney / interval precedence, then Holm) judges the variant significantly worse than the reference, oriented by the reference's `better`; `Improved` is the mirror. There is no comparison between non-reference variants and nothing is judged over time. Reports say "slower/faster than reference" (🔴/🟢) and never "regression" in prose; the enum and the Action output names (`regressed`, `improved`, ...) are kept for compatibility and in a matrix run count cells versus the reference. `fail-on-regression` is the **regression gate** for matrix runs: it requires an **explicit** `reference` (a declared baseline such as the shipped implementation); with a defaulted first-listed reference the run is rejected with static exit 2 `fail-on-regression in an N-way run needs an explicit 'reference' (the baseline to protect); set 'reference'`, because failing a job on an arbitrary column would be a hidden policy. The gate trips on a post-Holm Regressed cell over the threshold or any Invalid cell; with no `fail-on-regression`, `failed` is false whatever the cells are. The report prints a gate line (`gate: fail-on-regression 10% vs quick: passed|FAILED (...)`). If the explicit reference is later lost from the data, the run degrades to a notice-only report and the gate is skipped (passes) unless `dimensions-strict`. No separate gate flag is added: one existing name keeps the vocabulary single (alternative rejected below).

## Alternatives rejected
- **Reference = fastest overall or per row**: unstable across runs, breaks comment-to-comment comparison.
- **All-pairs matrix**: N(N-1)/2 tests, worse multiplicity, unreadable.
- **Gating on the defaulted reference** (or on "any variant slower than the fastest"): the gated column would change with input order; rejected in favour of requiring an explicit reference.
- **A new `gate`/`baseline` flag instead of reusing `fail-on-regression`**: a second name for one concept; rejected, the existing flag keeps its meaning with a stricter precondition in N-way.
